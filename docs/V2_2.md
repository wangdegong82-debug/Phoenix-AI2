# Phoenix AI 2.2

## What is now usable

Phoenix 2.2 connects the Android application to the FastAPI backend.

Android:
- Today's matches
- Match Lab
- 1X2 probabilities
- expected goals
- score paths
- tail-risk warnings
- evidence display
- Phoenix Chat
- API URL/token settings
- GitHub Release update checking

Backend:
- demo mode that works with no third-party API key
- API-Football adapter for real fixtures
- last-5 form
- H2H
- best-effort injuries
- best-effort 1X2 odds
- Phoenix Engine
- server-side OpenAI chat
- bearer-token Owner/Premium access

## Real football data

Set on the backend:

```text
FOOTBALL_DATA_PROVIDER=api-football
FOOTBALL_DATA_API_KEY=...
```

The adapter expects API-Sports / API-Football v3-compatible endpoints.

Not every API plan exposes injuries and odds. Phoenix treats them as best-effort fields and reports unavailable data in `evidence` instead of inventing it.

## Android server URL

Open Phoenix AI -> Settings and fill:

```text
https://YOUR_BACKEND_DOMAIN
```

Then tap `测试连接`.

## Security

Do not put:
- OpenAI API keys
- football provider API keys
- release signing keys

inside the APK.

Only the access token used to identify the app user is stored locally.

The current static Premium/Owner bearer tokens are an MVP. A production public app should replace them with user accounts, short-lived JWTs, subscription verification and server-side entitlement checks.
